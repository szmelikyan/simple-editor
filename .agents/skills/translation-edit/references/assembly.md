# Единый файл завершённых частей

Скрипт `scripts/assemble.py` использует только стандартную библиотеку Python 3. Он не выполняет редактуру и не доказывает смысловую полноту: перед `--reviewed` агент обязан выполнить редакторскую проверку. Не добавляй отчёт в передаваемый чистовой файл.

```sh
python3 <skill>/scripts/assemble.py init projects/<slug> --title 'Название' --language ru --output edited.fb2
python3 <skill>/scripts/assemble.py put projects/<slug> --id '553/1' --order 1 --file /path/to/reviewed.md --reviewed
python3 <skill>/scripts/assemble.py verify projects/<slug>
```

`--id` сохраняет исходную нумерацию; `--order` — явный числовой порядок в источнике, включая дробное значение для вставок. Не угадывай порядок по имени файла. Для нового проекта установи порядок из источника; если он не известен, уточни его до включения в общий файл. Тот же `id` заменяет старую редакцию без дубликата. Другим идентификаторам нельзя назначать одинаковый порядок.

`assembly.json` содержит все чистовые части и их SHA-256; мастер пересобирается целиком, не дописыванием фрагмента. Скрипт блокирует параллельную запись, проверяет канонические данные, порядок, дубликаты и соответствие общего файла перед изменениями. При ошибке разбирай причину; не удаляй состояние, чтобы обойти проверку.

Если общий файл потерян, но полный проверенный `assembly.json` сохранён, восстанови ВСЕ части:

```sh
python3 <skill>/scripts/assemble.py rebuild projects/<slug> --confirm
```

Если мастер изменён извне, сначала сохрани обе версии и согласуй изменения с каноническими частями. `rebuild` перезапишет мастер полным содержимым состояния — не используй его для обхода неразобранного расхождения. При потере состояния не создавай неполную замену под прежним именем: перечисли недоступные части и восстанови их из резервной копии. После сбоя между атомарными записями состояние содержит все части, а проверка блокирует новые изменения до восстановления полного мастера.

Выход скрипта содержит реальный список идентификаторов и число частей. Он не знает общего ожидаемого набора произведения: агент должен сопоставить его с порядком из `profile.md` и назвать известные пропуски. В общий файл входят только завершённые части; статус черновика хранится отдельно.

## FB2 и переход с Markdown

Сборщик по умолчанию создаёт `edited.fb2` (FictionBook 2, UTF-8 XML). Старые мастера `.md` поддерживаются. Канонические тексты в `assembly.json` остаются Markdown. Для проверенного существующего проекта:

```sh
python3 <skill>/scripts/assemble.py convert projects/<slug> --output edited.fb2
python3 <skill>/scripts/assemble.py verify projects/<slug>
```

`convert` проверяет прежний мастер и сохраняет все части. Существующий файл назначения не перезаписывается. Прежний мастер остаётся до проверки нового; после проверки полноты его можно удалить, чтобы он не устаревал под видом актуального файла.

Один начальный заголовок `# ` становится заголовком главы, обычные абзацы — `p`, соседние цитатные абзацы `> ` — блоком `cite`. Специальные символы и текст разделителей `***` сохраняются. Вложенные заголовки блокируют сборку до явного преобразования. Курсив `*текст*`, жирное `**текст**` и жирный курсив `***текст***` поддерживаются как для целого абзаца, так и для отдельных фрагментов, включая цитаты. Между выделенными фрагментами сохраняются пробелы и пунктуация. Маркеры преобразуются в `emphasis`/`strong`; отдельный разделитель `***` остаётся буквальным текстом. Поддерживается плоская разметка выделений, без вложенного Markdown. Иная Markdown-разметка остаётся буквальным текстом. Это не универсальный Markdown-парсер; неподдерживаемые элементы источника требуют отдельного разбора до сборки.

Автор, дата и жанр не угадываются: значения по умолчанию — «Автор не указан», «Дата не указана», `unrecognised`. Проверенные метаданные можно задать полями состояния `author` (имя/псевдоним), `date` (текст даты), `genre` (допустимый код FB2) с последующей пересборкой.

Сборка требует только Python 3.9+. Проверки сборщика из корня репозитория:

```sh
python3 -m unittest discover -s tests
```

Для отдельной проверки формата скачайте [официальную XSD-схему FB2](https://github.com/gribuser/fb2/blob/master/FictionBook.xsd) и зависимости `FictionBookLinks.xsd`, `FictionBookGenres.xsd`, `FictionBookLang.xsd` из того же репозитория в одну папку. При наличии `xmllint`:

```sh
xmllint --noout --schema /path/to/schema/FictionBook.xsd projects/<slug>/edited.fb2
```

XSD проверяет формат, а не полноту. Дополнительно сравнивайте текст и порядок всех абзацев `body/section` с каноническими главами, исключая только структурные маркеры Markdown. Эти проверки и чтение в приложении-читалке — разные проверки; не заявляйте проверку читалкой, если она не выполнялась.
